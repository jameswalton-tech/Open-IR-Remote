# Verification report

The local prototype passed 22 test groups on Node 24.18.0, Windows, with Python jsonschema 4.25.1, Pillow 12.3.0 and explicitly pinned date-time/URI helpers. `npm test` rebuilds the pinned schema validator and TypeScript before running tests. No tests were skipped. The added repository integration test checks that the pinned schema and validator match the main project byte for byte.

The differential corpus contains 119 synthetic acceptance cases with no JavaScript/Python acceptance differences. A separate test demonstrates the intentional stricter JavaScript decimal-precision rule. Coverage includes required fields, Unicode code-point bounds, unsigned32 limits, wider hexadecimal strings, date/URI examples, command counts, inherited defaults, missing protocol, unique IDs and primary representations, raw timing alternation and total count, Pronto syntax, extension limits, duplicate JSON keys, byte/depth limits, and importer output.

Core regressions preserve a supplied canonical command ID through handset and label renames, retain translated labels and vendor extensions, and reject missing protocol instead of falling back to NEC. Browser bundles execute in an isolated context without Node globals. A synthetic WebP passes the exact Python file validator; removing it produces a failure while the record-only validator reports assets unchecked.

CSV tests cover quoted commas and embedded newlines, Unicode, exact numeric spelling, -1 sentinels, mixed protocol variants, duplicate rows, malformed or missing headers, missing values, blank labels, incomplete submissions, 128/129/2499 command counts, exact source restoration and explicit CSV loss reporting. The latest acceptance policy rejects the whole submission for any incomplete row or more than 128 commands. Header overrides and extra JavaScript selection arguments cannot bypass this policy.

A read-only inventory independently confirmed 3,244 source CSVs, 114,154 rows, 102 nonempty protocol names, 1,958 blank labels, 68 files above 128 commands and a largest collection of 2,499 rows. Well-formed numeric values ranged from -1 to 996. It confirmed three headerless files, two malformed headers and four malformed four-column Denon rows. No repair was attempted.

The SDK then accepted 2,893 whole source submissions and ignored 351. Every accepted transient record passed the pinned authoritative Python validator. Only aggregate audit results were retained. No source codes or derivative records were bundled in the SDK or published. The audit supplied an explicit unknown handset identity for software validation; it did not establish a physical remote model.

Reproduce the synthetic checks with `npm ci`, `python -m pip install -r requirements.txt`, and `npm test`. Run `npm run example` for the commented usage example, `npm run measure` for browser and JSON sizes, and `npm pack --dry-run --json` for package size. The optional scripts/audit-irdb.mjs takes a local checkout path and reproduces the aggregate source audit without downloading data.

Remaining limits are documented in README.md. This is not an exhaustive conformance proof, browser matrix, fuzzing audit, licence clearance or playback qualification. It includes no protocol renderer or hardware adapter. The original reviewed checkout and Lightly worktree were not edited. Repository integration uses an isolated checkout; PR publication and merge are separately authorised by the user. No package or source-data publication, schedule or hardware operation is part of the SDK.

Independent review identified two format-compatibility gaps before PR publication. Both were corrected: explicit authority-compatible date/time checks replace Ajv date/time defaults, and requirements now pin the optional Python format validators and all transitive dependencies. The complete 22-group suite also passed in a newly created Python virtual environment containing only requirements.txt dependencies. The Python bridge checks helper availability and versions before validating any record.
